Explainer

How a read-through cache answers

The first read of a key misses and goes to the database; it leaves a copy in the cache, and every read after it is answered from memory until the copy expires.

The three steps

When it goes wrong

Stale reads

A row changed in the database is still served from the cache until its copy expires. Keep the time to live as short as the data's tolerance for being out of date.

A miss on a key no row has goes to the database every time. Cache the absence too, for a shorter time, so a flood of reads for a missing key does not reach the database.
