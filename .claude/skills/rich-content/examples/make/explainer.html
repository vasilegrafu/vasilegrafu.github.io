How it works

A read that misses, and fills the cache

Five steps, one diagram. Each step lights what it is about; the boxes never move.

The API keeps a copy of each order it has read in a cache. A read hits when the copy is there; when it is not, it misses, reads the database, and leaves a copy behind for the next read.

Watch

A miss that does not leave a copy behind will miss again on the next read.
